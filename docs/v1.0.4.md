# v1.0.4 Planning

## Theme

V1.0.4 should be a small follow-up focused on unit coverage reporting and targeted test hardening after the V1.0.3 testing framework redux.

Suggested branch scope:

- Add code coverage collection and reporting for .NET and Vitest.
- Add focused unit tests around important, high-risk functions from the V1.0.3 work.
- Keep screenshot, manifest, and Playwright parity tests as product evidence, not as the primary code coverage metric.
- Avoid pulling V1.1 capture replay, broader overlay product work, or new runtime behavior into this branch.

Suggested release title:

- `[v1.0.4] Add unit coverage reporting and targeted test hardening`

## Current Test Surface

The repo already has a substantial test base:

- C# xUnit tests under `tests/TmrOverlay.App.Tests/`.
- Browser-review and localhost Vitest tests under `tests/browser-overlays/`.
- Playwright layout/integration tests for browser review and localhost routes.
- Screenshot generation and validation profiles for browser review, localhost, Windows native overlays, installer screenshots, and manifest parity.
- Semantic validation matrices under `tools/validation/`, including V1.0.2 and V1.0.3 coverage manifests.

Important branch-start tooling state:

- `coverlet.collector` is already referenced by `tests/TmrOverlay.App.Tests/TmrOverlay.App.Tests.csproj`.
- The Windows CI workflow runs `dotnet test`, but does not collect or publish coverage.
- `vitest.config.mjs` configures JS unit tests, but does not configure coverage.
- `package.json` has targeted Vitest scripts, but no JS coverage script.
- Local macOS development cannot run the .NET test suite today because `dotnet` is not installed locally; .NET verification needs Windows CI or a Windows machine.

## Test Strategy

The useful split for this repo is to separate fast correctness checks from product-parity proof.

### Unit Tests

Unit tests should protect deterministic logic that does not need a renderer, server, browser, or Windows UI.

Best targets:

- Geometry and layout math such as `DesignV2SettingsLayout` and `OverlayContentSizing`.
- Model and state decisions such as `LiveTelemetryStore` and `BrowserOverlayModelFactory.TryBuild`.
- Diagnostics bundle classification and support evidence helpers.
- IBT candidate scoring and status handling.
- Settings migrations, defaults, option normalization, and durable schema behavior.

Value:

- Catch shared-contract drift before screenshot parity produces a large failure.
- Keep failures close to the function that made the wrong decision.
- Make coverage meaningful by exercising important decisions rather than only rendering paths.

### Functional Tests

Functional tests should prove user-visible behavior through a public boundary while still using deterministic fixtures.

Good examples:

- All Pit Service content disabled results in a non-renderable overlay model.
- Stream Chat settings patches update effective model evidence.
- Diagnostics bundles include triage files and exclude raw telemetry.
- Settings General preview reports the correct OBS size and semantic evidence.
- Product-hidden or unavailable overlays clear rows, points, graph data, and rendered-content evidence.

Value:

- Highest return for this codebase because many bugs are not isolated math errors; they are mismatches between settings, models, evidence, and rendered state.
- Tests the right contract surfaces without needing full screenshot generation every time.
- Gives clearer failures than screenshot parity when behavior is wrong but pixels are only a symptom.

### Integration Tests

Integration tests should prove the real surfaces work together.

Existing examples:

- Playwright browser review and localhost tests.
- Browser review, localhost, Windows native, and installer screenshot generation.
- Screenshot manifest validation and cross-surface parity comparison.
- Localhost hosted-service route tests with actual HTTP behavior.

Value:

- Required for this product because native Windows, browser review, localhost/OBS, diagnostics, and manifests can drift even when individual helpers pass.
- Proves that shared contracts are consumed consistently by real renderers and evidence emitters.
- Remains the final release gate for surface parity.

V1.0.4 should bias toward unit and functional coverage while keeping the existing integration lanes as release gates. The goal is faster failures with clearer causes, without weakening screenshot and manifest checks that catch real surface-only regressions.

## Coverage Tooling Plan

### .NET

Use the existing Coverlet collector path:

```powershell
dotnet test tmrOverlay.sln --configuration Release --no-restore --collect:"XPlat Code Coverage"
```

Add ReportGenerator after the test run to convert generated Cobertura files into:

- HTML coverage report artifact.
- Cobertura XML artifact for future services.
- GitHub Markdown summary for PR review.

Initial policy:

- Publish coverage but do not fail CI on a percentage threshold until the baseline is known.
- Exclude generated files and low-signal UI/paint-heavy paths before setting any gate.
- Prefer ratcheting thresholds later by meaningful areas, not one global number that hides important gaps.

Likely exclusions:

- Generated constants such as `OverlayGeometryContractValues.g.cs`.
- WinForms designer/paint-heavy surfaces where coverage would be noisy.
- Screenshot generator programs where validation output matters more than line percentage.
- Test projects, fixtures, and build artifacts.

### JavaScript

Add Vitest V8 coverage:

```bash
npm install --save-dev @vitest/coverage-v8
npm run test:coverage:js
```

The coverage script should run Vitest unit suites, not Playwright. Playwright remains valuable for layout and integration evidence, but it is slower and less useful as a first-pass line/branch coverage metric.

Initial script shape:

```json
"test:coverage:js": "vitest run --coverage"
```

Configure `vitest.config.mjs` to report:

- `text`
- `html`
- `lcov`
- `json-summary`

Initial exclusions should avoid generated artifacts, screenshot output, Playwright specs, and static fixture files.

## High-Priority Unit Test Targets

### Settings Layout Contract Helpers

Target file:

- `src/TmrOverlay.App/Overlays/SettingsPanel/DesignV2SettingsLayout.cs`

Why it matters:

- V1.0.3 fixed repeated settings parity failures where browser, native, and screenshot evidence disagreed on panel bounds, crop origins, control hit areas, support diagnostics rows, and text/value evidence.
- These helpers are now the shared native layout contract surface and should be directly tested.

Add tests for:

- `PreviewPanelBounds`, `PreviewSummaryRowBounds`, `PreviewModeControlBounds`, and preview body line bounds.
- `RegionTabsCropBounds`, including native canvas offset behavior.
- `FieldRowBounds`, `FieldLabelBounds`, `FieldValueBounds`, inline controls, right-aligned controls, and steppers.
- Support diagnostics rows, support bundle value bounds, support toggles, and action buttons.
- Stream Chat provider/url/channel rows, textbox bounds, and save button bounds.
- Overlay controls panel height for ordinary overlays, Standings, Relative, Gap To Leader, Car Radar, and Garage Cover.

Test style:

- Assert formulas from `OverlayGeometryContractValues.SettingsGeometry`.
- Do not copy standalone pixel literals into tests unless the value is itself a generated contract constant.

### Browser Overlay Model Factory

Target file:

- `src/TmrOverlay.App/Overlays/BrowserSources/BrowserOverlayModelFactory.cs`

Why it matters:

- It owns production browser/localhost display models and much of the semantic evidence contract.
- The Gap To Leader graph and effective-settings evidence paths are complex and high impact.

Add focused black-box `TryBuild` tests for:

- Gap To Leader same-lap vs lapped graph behavior.
- Graph-off and trend-only settings.
- Focus switch behavior and stale point pruning.
- Selected series limits and point caps under repeated polling.
- Effective-settings evidence for hidden/no-content overlays.
- Product-hidden models clearing graph, points, rows, and rendered content evidence.

Avoid testing private methods directly unless no reasonable public seam exists. Prefer deterministic snapshots and settings inputs.

### Diagnostics Bundle Semantic Evidence

Target file:

- `src/TmrOverlay.App/Diagnostics/DiagnosticsBundleService.cs`

Why it matters:

- V1.0.3 exposed Windows-only CI risk in diagnostics bundle tests.
- Support diagnostics are now a key triage artifact for users and CI parity work.

Add tests for:

- Stable semantic keys for support diagnostics detail rows.
- Toggle selected/on/off state evidence.
- Bundle entries for coverage, overlay geometry contract, browser overlay metadata, and shared settings contract.
- OS-stable triage file inclusion.
- Freshness-sensitive fixtures that do not expire during slower CI runs.

Keep raw telemetry exclusion tests strict.

### IBT Analysis Candidate Selection

Target file:

- `src/TmrOverlay.App/Telemetry/IbtAnalysisService.cs`

Why it matters:

- IBT sidecar analysis chooses between candidate telemetry files and can silently pick the wrong post-session file if scoring regresses.
- Current tests cover the main synthetic parse path and one longer-file selection scenario, but the scoring edge cases deserve direct coverage.

Add tests for:

- Coverage penalty when candidate duration or record count is too small for the capture.
- Timestamp window distance when disk start time is known.
- Last-write fallback when manifest or disk start time is unavailable.
- Malformed or missing status recovery.
- Stable skipped status when candidate files are absent or too young.

### Localhost State And Hosted Service

Target files:

- `src/TmrOverlay.App/Localhost/LocalhostOverlayState.cs`
- `src/TmrOverlay.App/Localhost/LocalhostOverlayHostedService.cs`

Why it matters:

- Localhost/OBS route evidence is now part of parity and diagnostics.
- Request classification, caching headers, client identity, and page events need to remain stable.

Add tests for:

- OBS-like client classification from query parameters and user agent.
- Per-route request counters and status counters.
- Browser-source page events with bounded samples.
- Product-hidden/no-content response semantics.
- Cache headers on model and page routes.

### Overlay Content Sizing

Target files:

- `src/TmrOverlay.App/Overlays/Content/OverlayContentSizing.cs`
- `src/TmrOverlay.App/Overlays/Content/OverlayContentColumnSettings.cs`

Why it matters:

- V1.0.3 moved many layout numbers into shared geometry contracts.
- Future regressions should fail in unit tests before screenshot manifest parity finds them.

Add tests for:

- Fuel Calculator race vs non-race height calculations from contract geometry.
- Pit Service metric-only vs tire-grid width/height.
- Session Weather non-race reductions.
- Gap To Leader graph-only, trend-only, graph-plus-trend, and disabled states.
- Header/footer chrome height adjustments by session gate.
- Session-specific content toggles.

### Validation And Comparator Tools

Target files:

- `tools/validate_overlay_screenshots.py`
- `tools/compare_screenshot_manifests.py`
- `tools/validation/overlay-evidence-contract.mjs`

Why it matters:

- These tools are now release-critical. A validator bug can block CI or hide a real parity regression.

Add small synthetic tests for:

- Settings geometry evidence comparison.
- Text/value evidence semantics.
- Region crop origin normalization.
- Support diagnostics semantic key comparison.
- Manifest parity failures that should remain strict.
- Explicit unsupported-surface reasoning.

Use minimal synthetic manifests rather than full screenshot artifacts for unit-level coverage.

## CI Plan

Add a dedicated coverage lane or extend existing lanes carefully:

1. Keep existing Windows tests as the correctness gate.
2. Add .NET coverage collection in Windows CI after restore.
3. Generate and upload a coverage artifact.
4. Add JS Vitest coverage in Ubuntu CI.
5. Upload JS coverage artifacts.
6. Add a short coverage summary to the job summary.

Do not make initial coverage red on percentage. First CI should establish:

- Baseline line/branch coverage.
- Which files need exclusions.
- Which important functions are currently untested.
- Whether coverage collection materially slows CI.

## Initial Coverage Implementation

First reporting-only coverage pass:

- .NET coverage uses the existing Coverlet collector and emits Cobertura from the Windows CI coverage lane.
- ReportGenerator converts .NET Cobertura output into HTML, Cobertura, and GitHub Markdown summary artifacts, with generated/designer files filtered from the report.
- JavaScript coverage uses Vitest V8 coverage through `npm run test:coverage:js`.
- `vitest.config.mjs` emits text, HTML, lcov, and JSON summary reports while excluding generated/static/screenshot artifacts.
- CI uploads `dotnet-coverage` and `javascript-coverage` artifacts and writes coverage summaries to the GitHub job summary.
- No coverage percentage threshold is enforced in the initial baseline pass.

## Acceptance Criteria

V1.0.4 should be considered complete when:

- .NET coverage is collected in CI and uploaded as an artifact.
- JS Vitest coverage is collected in CI and uploaded as an artifact.
- Coverage summaries are easy to read from the CI run.
- Generated/noisy files are excluded from coverage noise.
- Focused unit tests exist for the highest-risk V1.0.3 areas listed above.
- Existing screenshot and parity validation remains intact.
- No coverage threshold is added until the baseline has been reviewed.

## Follow-Up After Baseline

After the first green coverage run, decide whether to add thresholds. Prefer a staged policy:

- Start with reporting only.
- Add low project-wide minimums only after exclusions are correct.
- Add higher thresholds around pure business logic and contract helpers.
- Ratchet thresholds upward only when new tests actually cover important behavior.

Candidate future threshold areas:

- `TmrOverlay.Core` live telemetry models and settings migrations.
- Browser model factory evidence helpers.
- Settings layout contract helpers.
- Overlay content sizing.
- Diagnostics bundle helpers.
- Localhost state and request tracking.
- Validation/comparator logic.
