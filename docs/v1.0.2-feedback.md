## Analysis - v1.0.1 Visual And Runtime Feedback

Scope: review the new visual/runtime feedback from v1.0.1 and identify the likely product and implementation work for v1.0.2. This is analysis only; no product changes have been made yet.

Cross-cutting findings:

- Several issues are native/localhost parity bugs rather than isolated CSS or WinForms bugs. Relative, Standings, and Gap To Leader need one settings/model contract that native, browser review, and localhost prove with the same deterministic fixtures.
- Gap To Leader has the highest duplication risk. Trend selection, sticky series retention, metrics, threat labelling, and graph rendering exist in multiple native/browser paths, so fixes should either consolidate shared logic or add parity tests across every active path.
- Layout failures need screenshot and manifest evidence. The `Pit` column and Gap last-lap clipping are small visual issues, but the validation needs to prove the rightmost text is visible on native, browser review, and localhost before the branch is considered complete.

### V102-013 - Relative header colours

Different Relative headers are using different colour treatments. This most likely comes from a mix of legacy native chrome tones, design V2 tokens, and browser CSS defaults rather than one shared Relative-specific rule.

Likely work: standardize Relative header colour through shared `OverlayTheme`/chrome tokens, then check native and localhost with equivalent fixture state. This should not introduce per-overlay one-off colours unless the theme already defines them.
